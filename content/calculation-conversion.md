앞 수업에서는 변수에 첫 값을 넣고 변경하는 방법을 살펴봤습니다. 이번에는 그 값들을 계산에 사용합니다. 같은 7과 2라도 정수로 나누는지, 소수 부분이 있는 수로 나누는지에 따라 결과가 달라집니다. 결과를 저장할 변수의 타입만 바꿔서는 이미 끝난 계산을 되돌릴 수 없습니다.

이 수업은 계산에 참여하는 값의 타입, 연산자가 묶이는 방식, 변환이 일어나는 위치를 함께 읽는 연습입니다. 예제는 C++20 콘솔 프로젝트에서 하나씩 실행합니다. 완전한 실행 예제에는 `main`이 있으며, 짧은 코드 조각은 설명용입니다.

## 이 수업을 마치면

1. 정수 나눗셈과 실수 나눗셈의 출력을 예측하고, 계산 전에 타입을 바꾸어 원하는 결과를 얻을 수 있습니다.
2. 산술·비교·논리 연산을 읽고, 괄호와 `bool` 변수로 계산 의도를 표현할 수 있습니다.
3. 중괄호의 좁히기 변환 진단과 명시적 변환을 구분하고, 타입의 범위를 벗어나는 계산을 피해야 하는 이유를 설명할 수 있습니다.

## 1 계산에는 값뿐 아니라 타입도 참여합니다

`int`는 횟수나 개수처럼 정수로 다룰 값에 어울립니다. `double`은 거리나 비율처럼 소수 부분이 필요한 값에 사용할 수 있습니다. `bool`은 준비 여부처럼 참과 거짓으로 나타낼 값에 사용합니다. 여기까지는 앞 수업에서 익힌 구분입니다.

이번에 추가할 내용은 “계산 결과에도 타입이 있다”는 점입니다. `7 / 2`에서는 두 값이 모두 `int`이므로 정수 나눗셈을 합니다. `7.0 / 2`에서는 7.0이 `double`이며, 이 계산에서는 다른 피연산자 2도 `double`로 변환되어 부동소수점 나눗셈을 합니다. 피연산자는 연산에 참여하는 값을 뜻합니다. [참고 1]

정수와 부동소수점의 차이를 셀 수 있는 물건과 측정할 수 있는 양에 빗대어 보겠습니다. 물건을 몇 개씩 나눌 때와 길이를 나눌 때는 필요한 결과의 형태가 다릅니다. 실제 `double`이 모든 실수를 정확히 표현한다는 뜻은 아닙니다.

## 2 기본 연산과 괄호를 읽습니다

기본 산술 연산자는 `+`, `-`, `*`, `/`, `%`입니다. 각각 더하기, 빼기, 곱하기, 나누기, 나머지를 뜻합니다. 이번 수업에서 `%`는 정수끼리 사용합니다. `double` 값에 `%`를 적용하는 것은 허용되지 않습니다.

`2 + 3 * 4`는 `2 + (3 * 4)`로 묶이므로 14입니다. `(2 + 3) * 4`는 괄호 안의 합을 곱하므로 20입니다. 곱셈·나눗셈·나머지는 덧셈·뺄셈보다 우선순위가 높습니다. 같은 우선순위의 이항 산술 연산은 왼쪽부터 묶입니다. `20 / 5 * 2`는 `(20 / 5) * 2`여서 8이고, `20 / (5 * 2)`는 2입니다.

주의할 점이 있습니다. 연산자의 우선순위와 결합 방향은 “식이 어떻게 묶이는가”를 설명합니다. 모든 피연산자가 실행 중 왼쪽부터 평가된다는 보장은 아닙니다. 이번 예제처럼 단순한 값만 읽는 식에서는 결과 계산에 집중해도 좋지만, 값을 바꾸는 연산이나 함수 호출을 복잡한 식 하나에 몰아넣지는 않습니다. [참고 2]

대입에도 같은 원리가 적용됩니다. `score = score + 5;`는 현재 `score` 값에 5를 더한 결과를 `score`에 저장합니다. 이처럼 값을 누적하는 경우 `score += 5;`라고 짧게 쓸 수 있습니다. 이번에는 서로 다른 타입이 섞인 복합 대입까지 확장하지 않고 `int`의 작은 값으로 연습합니다.

## 3 예제 01 정수 나눗셈과 나머지

토큰 7개를 두 사람에게 같은 개수로 나눈다고 가정하겠습니다. 각 사람에게 몇 개씩 주고 몇 개가 남을까요? 코드를 실행하기 전에 네 줄의 결과를 적어 보세요.

```cpp
#include <iostream>

int main()
{
    int tokens{7};
    int people{2};
    int each{tokens / people};
    int leftover{tokens % people};

    std::cout << each << std::endl;
    std::cout << leftover << std::endl;
    std::cout << -7 / 3 << std::endl;
    std::cout << -7 % 3 << std::endl;
}
```

예상 출력입니다.

```text
3
1
-2
-1
```

정수 나눗셈은 수학적인 몫의 소수 부분을 0 방향으로 버립니다. `7 / 2`는 3이고, `-7 / 3`은 -2입니다. 음수에서 더 작은 정수로 내려가는 “내림”과는 다릅니다.

나머지는 몫과 함께 읽습니다. 나눗셈이 유효하고 몫을 결과 타입으로 표현할 수 있다면 `(a / b) * b + a % b`가 `a`와 같습니다. -7을 3으로 나눈 경우 `(-2) * 3 + (-1)`이 -7입니다. 이때 0이 아닌 나머지의 부호는 나누어지는 값의 부호와 같습니다. [참고 1]

이 예제의 `people`은 2입니다. 정수 나눗셈과 나머지에서 나누는 값이 0이면 미정의 동작입니다. 또한 `int`의 최솟값을 -1로 나누어 결과를 `int`로 표현할 수 없는 경우도 미정의 동작입니다. 그런 식을 실행해 “어떤 숫자가 나오나”로 규칙을 배우면 안 됩니다. 이번 실습에서는 나누는 값이 0이 아니고 결과가 범위 안인 값만 사용합니다.

실습으로 `tokens`를 8, `people`을 3으로 바꾸어 보세요. 몫은 2, 나머지는 2가 되어야 합니다. 다음으로 `tokens`를 0으로 바꾸면 두 결과 모두 0입니다. `people`까지 0으로 바꾸지는 않습니다.

## 4 예제 02 변환은 나누기 전에 합니다

이번에는 7을 2로 나눈 비율 3.5를 얻으려 합니다. 결과 변수를 `double`로 만들면 충분할까요?

```cpp
#include <iostream>

int main()
{
    int total{7};
    int count{2};
    double storedAfter = total / count;
    double convertedAfter = static_cast<double>(total / count);
    double convertedBefore = static_cast<double>(total) / count;

    std::cout << storedAfter << std::endl;
    std::cout << convertedAfter << std::endl;
    std::cout << convertedBefore << std::endl;
    std::cout << 7.0 / 2 << std::endl;
}
```

예상 출력입니다. 기본 출력 설정에서는 `double`의 정수 값 3도 3으로 보일 수 있습니다.

```text
3
3
3.5
3.5
```

`storedAfter`의 오른쪽에서는 `int`끼리 먼저 나누어 3이 됩니다. 그다음 `double`로 변환하여 저장합니다. `convertedAfter` 역시 나눗셈이 끝난 3을 `double`로 바꿉니다. 버린 소수 부분은 돌아오지 않습니다.

`static_cast<double>(total)`은 `total`의 값을 `double`로 변환한 결과를 만듭니다. `total` 변수 자체의 타입을 바꾸지는 않습니다. `convertedBefore`의 식에서는 나눗셈 전에 한쪽이 `double`이 되었고, 다른 쪽도 이 연산을 위해 `double`로 변환됩니다. 그래서 3.5가 나옵니다.

정확한 계산 흐름은 다음 세 줄로 구분할 수 있습니다. 이 표기는 생성 그림이 아니라 예제의 동작을 직접 적은 것입니다.

- `total / count`를 계산한 뒤 저장: `int` 7 `/` `int` 2 → `int` 3 → `double` 3
- 나눗셈 결과를 변환: `int` 7 `/` `int` 2 → `int` 3 → `double` 3
- `total`을 먼저 변환: `double` 7 `/` `double` 2 → `double` 3.5

여기서는 `=` 초기화를 사용해 계산 후 변환되는 지점을 보여 줬습니다. 중괄호 초기화는 일부 암시적 변환을 더 엄격하게 제한하므로, 두 표기를 무조건 바꿔 쓸 수는 없습니다. 다음 절에서 그 차이를 확인합니다.

## 5 좁히기 진단과 명시적 변환

부동소수점 값을 정수로 바꾸면 소수 부분을 잃을 수 있습니다. 아래 두 줄은 의도한 컴파일 오류 예제입니다. 정상 실행 예제와 분리하여 한 줄씩 빌드해 보세요.

```cpp
int count{3.9};
int exactLooking{3.0};
```

두 줄 모두 중괄호 초기화에서 허용되지 않는 좁히기 변환입니다. 3.0처럼 눈으로 보기에 소수 부분이 0이어도, 부동소수점 타입에서 정수 타입으로 바꾸는 경우는 이 규칙에 해당합니다. 컴파일러는 진단해야 하며, 수업의 엄격한 빌드 설정에서는 빌드가 실패합니다. [참고 3]

정수 부분만 사용하려는 의도가 분명하고 변환 결과가 표현 범위 안이라면 명시적으로 변환할 수 있습니다.

```cpp
int whole{static_cast<int>(3.9)};
int negativeWhole{static_cast<int>(-3.9)};
```

각 값은 3과 -3입니다. 여기서도 반올림하거나 아래쪽 정수로 내리는 것이 아니라 0 방향으로 소수 부분을 버립니다. 중괄호가 받아들이는 것은 이미 `int`로 변환된 값입니다. 앞의 `static_cast`가 없던 일이 되는 것은 아닙니다.

`static_cast`는 “이 변환을 의도했다”는 표기이지, 값의 범위를 검사하는 장치가 아닙니다. 소수 부분을 버린 결과를 대상 정수 타입에 담을 수 없으면 부동소수점에서 정수로 바꾸는 동작 자체가 미정의 동작입니다. NaN이나 무한대를 `int`로 바꾸는 것 역시 안전한 우회로가 아닙니다. 이번에는 3.9처럼 작은 유한 값만 변환합니다. [참고 4]

정수에서 `double`로 바꾸는 것도 언제나 정확한 것은 아닙니다. 모든 정수를 `double`로 정확하게 표현할 수 있는 것은 아니기 때문입니다. 이번 예제의 7과 2 같은 작은 값과 큰 정수 전체를 같은 조건으로 생각하지 않습니다.

## 6 예제 03 비교 결과를 `bool`로 저장합니다

숫자의 크기를 비교하면 `bool` 결과를 얻습니다. `==`는 같은지, `!=`는 다른지, `<`와 `>`는 작은지와 큰지, `<=`와 `>=`는 같음까지 포함하여 비교합니다. 값을 넣는 `=`와 같은지 비교하는 `==`는 다릅니다.

두 조건을 연결할 때 `&&`는 둘 다 참인지, `||`는 하나라도 참인지, `!`는 참과 거짓을 뒤집는 데 사용합니다. 다음 예제에서는 시작 조건을 이름으로 나누어 적었습니다.

```cpp
#include <iostream>

int main()
{
    int tickets{2};
    int required{2};
    bool hasTickets{tickets >= required};
    bool connected{true};
    bool canStart{hasTickets && connected};
    bool needsAttention{!connected || tickets == 0};

    std::cout << std::boolalpha;
    std::cout << hasTickets << std::endl;
    std::cout << canStart << std::endl;
    std::cout << needsAttention << std::endl;
}
```

예상 출력입니다.

```text
true
true
false
```

`std::boolalpha`는 이후 `bool` 출력을 1과 0 대신 `true`와 `false`로 보여 주는 스트림 설정입니다. `bool` 변수의 값이나 타입을 바꾸는 연산은 아닙니다.

내장 `&&`는 왼쪽이 `false`이면 오른쪽을 평가하지 않습니다. 내장 `||`는 왼쪽이 `true`이면 오른쪽을 평가하지 않습니다. 이를 단락 평가라고 합니다. 다음 수업에서 조건에 따라 실행을 나누는 코드를 작성할 때 이어서 사용합니다. 이번에는 비교와 논리 연산으로 `bool` 값을 만드는 데 집중합니다. [참고 5]

숫자를 `bool`로 변환하면 0은 `false`, 0이 아닌 값은 `true`가 됩니다. 음수 -3도 `true`입니다. 다만 “숫자이면 `bool` 중괄호에 아무 값이나 넣을 수 있다”는 뜻은 아닙니다. `bool flag{2};`는 좁히기 변환이므로 허용되지 않습니다. 가능하면 `tickets > 0`처럼 무엇을 확인하는지 드러나는 비교식을 사용합니다.

실습으로 `connected`를 `false`로 바꾸어 보세요. `hasTickets`는 그대로 `true`지만 `canStart`는 `false`, `needsAttention`은 `true`가 됩니다. `connected`는 `false`로 둔 채 `tickets`를 1로 바꿨을 때도 결과를 따로 예측해 보세요.

## 7 타입의 범위는 계산 중에도 중요합니다

`int`가 저장할 수 있는 값에는 최솟값과 최댓값이 있습니다. 정확한 범위는 구현에 따라 달라지므로 “`int`는 모든 환경에서 반드시 32비트”라고 가정하지 않습니다. 현재 구현의 범위를 확인하는 도구로 `<limits>`의 `std::numeric_limits`를 사용할 수 있습니다.

아래는 완전한 실행 예제입니다. 템플릿 문법 자체는 뒤에서 배우며, 지금은 `int`의 범위를 조회하는 정해진 표기로 읽습니다.

```cpp
#include <iostream>
#include <limits>

int main()
{
    std::cout << std::numeric_limits<int>::lowest() << std::endl;
    std::cout << std::numeric_limits<int>::max() << std::endl;
}
```

이번 검증 환경에서는 -2147483648과 2147483647이 출력되었습니다. 이는 사용한 환경의 관측 결과이며 모든 C++20 구현에 고정된 수치가 아닙니다.

부호 있는 정수의 산술 결과가 해당 타입의 범위를 벗어나면 미정의 동작입니다. 최댓값에 1을 더하면 반드시 최솟값으로 돌아온다고 가르칠 수 없습니다. “이번 실행에서 돌아오는 것처럼 보였다”는 관찰도 언어가 그 동작을 보장한다는 뜻은 아닙니다. [참고 6]

큰 결과를 `long long` 변수에 저장하더라도 오른쪽의 `int` 계산에서 이미 범위를 넘었다면 늦습니다. 필요한 경우 연산 전에 더 넓은 타입으로 변환하고, 그 타입의 범위 안인지도 확인해야 합니다. 나눗셈을 끝낸 뒤 `double`로 저장해도 소수 부분을 되찾지 못했던 것과 비슷하게, 결과를 받을 타입만 살피는 것으로는 충분하지 않습니다.

`unsigned int` 산술은 부호 있는 정수와 다르게 정해진 범위를 기준으로 순환합니다. 예를 들어 `unsigned int`의 최댓값에 `1u`를 더한 결과는 0입니다. 끝의 `u`는 `unsigned` 정수 리터럴임을 나타냅니다. 그렇다고 일반적인 개수 계산에서 범위 초과를 무시해도 된다는 뜻은 아닙니다. 결과 0이 프로그램의 의도와 맞는지는 별도 문제입니다.

`int`와 `unsigned int`를 섞을 때도 주의합니다. `int`의 -1이 `unsigned int`의 1보다 작은지 비교하면, 이 조합에서는 -1이 `unsigned int`로 변환되어 비교 결과가 `false`가 됩니다. 모든 혼합 계산이 항상 `unsigned`로 바뀐다는 뜻은 아닙니다. 이번 단계에서는 같은 의미의 수에 일관된 타입을 사용하고, 혼합 부호 경고를 이유 없이 지우지 않는 습관을 먼저 들입니다.

## 8 `double`도 수학의 실수 전체는 아닙니다

`double`은 유한한 공간으로 값을 표현하므로 표현 범위와 정밀도에 한계가 있습니다. 정밀도는 “소수점 아래 몇 자리까지 무조건 정확하다”는 규칙과 다릅니다. 값의 크기와 표현 방식도 관계됩니다.

특히 흔한 이진 부동소수점 환경에서는 0.1 같은 십진 소수를 정확하게 나타내지 못합니다. 계산 결과의 출력이 익숙한 소수처럼 보여도 내부 값이 수학적인 값과 정확히 같다고 결론 내릴 수 없습니다. 그렇다고 모든 부동소수점 비교를 금지하거나, 아무 상황에서나 같은 작은 오차 상수를 쓰는 것도 답은 아닙니다. 어떤 오차를 허용할지는 문제의 단위와 규모에 맞춰 정해야 합니다.

이 수업에서는 3.5와 3.75처럼 결과를 확인하기 쉬운 값으로 변환 위치를 배웁니다. 정밀도 분석과 오차를 고려한 비교는 수치 관련 후속 내용에서 확장합니다. 중요한 것은 `double`로 바꾸면 모든 계산 문제가 자동으로 해결되는 것은 아니라는 점입니다.

## 9 직접 확인할 문제

### 문제 1 괄호에 따른 차이

`18 / 4 * 2`와 `18 / (4 * 2)`의 결과를 각각 예상하고, `int` 변수 두 개에 저장해 출력해 보세요. 두 식이 어떻게 묶이는지도 적어 보세요.

### 문제 2 평균을 고치기

`int total{11};`과 `int count{4};`가 있습니다. `double average = total / count;`가 2.75를 출력하도록 오른쪽 식을 수정해 보세요. `total`과 `count`의 선언 타입은 바꾸지 않습니다.

### 문제 3 음수 나눗셈

`-11 / 4`와 `-11 % 4`의 결과를 예상해 보세요. 몫에 4를 곱하고 나머지를 더했을 때 -11이 되는지도 확인해 보세요.

### 문제 4 변환 의도 설명하기

`int whole{4.8};`이 왜 허용되지 않는지 설명해 보세요. 소수 부분을 버려 4를 얻으려는 의도를 명시적으로 표현하되, 이 변환이 범위 검사까지 해 주는지 답해 보세요.

### 문제 5 입장 조건

`int tickets{1};`과 `bool connected{false};`가 있습니다. `tickets >= 2 && connected`, `tickets >= 2 || connected`, `!connected`의 결과를 예상하고 `std::boolalpha`로 출력해 보세요.

### 문제 6 안전한 실행과 잘못된 주장

다음 두 주장에서 잘못된 부분을 찾아 보세요. 위험한 계산을 직접 실행할 필요는 없습니다.

- “`int` 최댓값에 1을 더해도 다음 음수로 넘어가니까 안전하다.”
- “결과를 `double`에 넣었으므로 `total / count`에서 소수 부분이 보존된다.”

## 10 해설

### 문제 1 정답

`18 / 4 * 2`는 `(18 / 4) * 2`이므로 `4 * 2`, 즉 8입니다. `18 / (4 * 2)`는 `18 / 8`이므로 2입니다. 정수끼리 나누는 각 지점에서 소수 부분을 버립니다.

### 문제 2 정답

오른쪽을 `static_cast<double>(total) / count`로 바꾸면 2.75를 얻습니다. `static_cast<double>(total / count)`는 이미 정수 나눗셈으로 얻은 2를 바꾸므로 해결되지 않습니다.

### 문제 3 정답

몫은 -2, 나머지는 -3입니다. `(-2) * 4 + (-3)`은 -11입니다. `-11 / 4`를 -3으로 예상했다면 0 방향 절삭과 내림을 혼동한 것입니다.

### 문제 4 정답

부동소수점에서 정수로의 변환은 중괄호 초기화의 좁히기 변환 규칙에 걸립니다. `int whole{static_cast<int>(4.8)};`처럼 의도를 적을 수 있으며 값은 4입니다. 다만 `static_cast`는 범위 검사를 하지 않습니다. 이 예제의 작은 유한 값이 `int` 범위 안이라는 전제를 다른 값 전체에 확대하면 안 됩니다.

### 문제 5 정답

결과는 차례로 `false`, `false`, `true`입니다. `tickets >= 2`가 `false`이고 `connected`도 `false`이기 때문입니다. 입력을 `tickets{2}`, `connected{false}`로 바꾸면 차례로 `false`, `true`, `true`가 됩니다.

### 문제 6 정답

부호 있는 정수의 산술 범위 초과는 미정의 동작이므로 순환을 보장하지 않습니다. 두 번째 주장은 결과를 저장하는 시점과 계산 시점을 혼동했습니다. 피연산자가 모두 `int`라면 먼저 정수 나눗셈을 하므로, 소수 부분이 필요할 때는 계산 전에 알맞은 타입으로 변환해야 합니다.

## 이번 수업에서 기억할 것

계산을 읽을 때는 결과 변수만 보지 않고, 연산에 참여하는 값의 타입부터 확인합니다. 괄호는 묶임을 명확하게 하고, 변환 위치는 결과에 영향을 줍니다. 중괄호의 진단과 컴파일러 경고는 이유를 이해하고 수정해야 합니다. 명시적 변환으로 경고를 숨기는 것만으로 안전성이 생기지는 않습니다.
