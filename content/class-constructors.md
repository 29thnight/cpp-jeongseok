## 유효한 상태로 객체 만들기, 멤버 초기화, 접근 제어

> 이번 수업의 질문: 값을 한데 묶는 데서 한 걸음 더 나아가, 그 값이 지켜야 할 규칙을 어디에 둘까요?

### 학습 목표
- `public`과 `private`로 외부에서 사용할 기능과 내부 데이터를 구분합니다.
- 생성자의 선언 형태와 멤버 초기화 목록을 작성하고, 멤버의 선언 순서가 초기화 순서임을 설명합니다.
- 객체를 만들 때뿐 아니라 값을 바꿀 때에도 같은 규칙을 유지합니다.

앞 수업에서 `struct`로 관련된 값을 묶었습니다. 이번에는 **아무 값이나 들어가면 곤란한 데이터**를 다룹니다. 상속, 예외 처리, 동적 메모리는 사용하지 않습니다. 조회 함수 끝의 `const`는 “이 함수는 객체의 일반 데이터 멤버를 변경하지 않는다”는 표시로만 읽어 두세요. 자세한 사용은 다음 수업에서 살펴봅니다.

## 1. 값에 규칙이 생기면 무엇이 달라질까요?

프로그램의 음량 설정을 정수로 표현한다고 가정하겠습니다. 이 프로그램에서 허용하는 범위는 0부터 100까지입니다. 이는 C++의 음량 규격이 아니라 **우리가 정한 가상 프로그램의 규칙**입니다.

값을 공개해 두면 호출하는 쪽마다 범위를 확인해야 합니다. 한 곳에서 검사하더라도 다른 곳에서 135를 대입하면 규칙이 깨집니다. “개발자가 조심한다”는 약속만으로는 변경 지점을 관리하기 어렵습니다.

이번 설계에서는 다음과 같이 역할을 나눕니다.

| 구분 | 맡길 일 |
|---|---|
| 데이터 멤버 | 현재 음량 저장 |
| 생성자 | 처음부터 정해진 범위의 값으로 시작 |
| 조회 함수 | 저장된 값 확인 |
| 변경 함수 | 새 요청에도 같은 범위 규칙 적용 |

객체가 사용 가능한 동안 계속 성립해야 하는 조건을 **불변식(invariant)**이라고 부릅니다. 이 예제의 불변식은 `0 <= level_ && level_ <= 100`입니다. “값이 전혀 변하지 않는다”는 뜻이 아니라, **값이 변해도 조건은 유지한다**는 뜻입니다.

## 2. public은 사용 방법, private는 내부 표현

`public:` 아래의 멤버는 외부에서 이름을 사용해 접근할 수 있습니다. `private:` 아래의 멤버 이름은 일반적인 외부 코드에서 직접 사용할 수 없습니다. 클래스의 멤버 함수에서는 그 클래스의 private 멤버에 접근할 수 있습니다. 친구 선언에 관한 예외는 후속 수업에서 다룹니다.

접근 지정자는 다음 접근 지정자가 나타나거나 클래스 정의가 끝날 때까지 적용됩니다. `class`의 기본 멤버 접근은 `private`, `struct`의 기본 멤버 접근은 `public`입니다. 둘 다 클래스 타입이며 생성자와 멤버 함수를 가질 수 있습니다. 상속을 사용할 때에도 기본 접근에 차이가 있으나 이 수업의 범위는 아닙니다. 따라서 “struct에는 데이터만, class에는 함수도 넣는다”는 구분은 맞지 않습니다. [C++20 초안: 멤버 접근 제어](https://timsong-cpp.github.io/cppwp/n4861/class.access)

다음 예제는 **의도적으로 컴파일에 실패**합니다. 성공 실행용 예제와 별도로 다루세요.

```cpp
class Meter {
private:
    int level_{30};

public:
    int level() const
    {
        return level_;
    }
};

int main()
{
    Meter meter{};

    meter.level_ = 150; // Intentional access error.
}
```

`main`에서 `meter.level_`라는 private 멤버 이름에 접근하므로 오류입니다. `meter.level()`은 public 조회 함수이므로 사용할 수 있습니다. 컴파일러에 따라 오류 문구와 번호는 다를 수 있습니다.

`private`는 암호화나 운영체제의 보안 경계가 아닙니다. 외부 코드가 내부 표현에 직접 의존하지 않게 하고, 변경 경로를 관리하는 언어 장치입니다. public 함수가 범위 밖의 값을 그대로 대입한다면 private 데이터라도 규칙은 깨집니다.

## 3. 생성자는 객체가 시작하는 상태를 정합니다

생성자는 해당 클래스의 객체를 초기화할 때 사용됩니다. 클래스 안에서는 `Volume(...)`처럼 **클래스 이름을 사용한 형태**로 선언하며, 반환형을 쓰지 않습니다. `void`도 붙이지 않습니다. 일반 함수처럼 결과값을 반환하는 함수가 아닙니다. 엄밀히 말해 표준에서 생성자 자체는 이름을 갖지 않는 특별한 함수로 다룹니다. [C++20 초안: 생성자](https://timsong-cpp.github.io/cppwp/n4861/class.ctor)

이 수업에서는 범위를 벗어난 요청을 가까운 끝값으로 보정합니다. 음수는 0, 100보다 큰 값은 100으로 바꿉니다. 입력을 거절하거나 오류를 알려 주는 설계도 가능하지만, 그것은 별도의 정책입니다. 보정이 언제나 옳은 방법인 것은 아닙니다.

![왼쪽에는 빈 파란 케이스와 구, 사각형, 막대 모양의 부품이 놓여 있고, 오른쪽에는 같은 부품들이 케이스 안의 자리에 맞게 놓여 있습니다.](/cpp-jeongseok/assets/illustrations/03-2-construction.webp)

*그림 1. AI 생성 개념 일러스트. 흩어진 부품을 맞추어 하나의 구성을 완성하듯, 생성자는 객체가 의도한 초기 상태를 갖도록 작성합니다. 실제 메모리 배치나 초기화 순서를 나타낸 그림은 아닙니다.*

그림의 완성 표시는 C++가 업무 규칙을 자동으로 알아서 검사한다는 뜻이 아닙니다. 다음 예제에서는 우리가 작성한 `boundedLevel` 함수가 범위를 맞춥니다.

```cpp
#include <iostream>

int boundedLevel(int requested)
{
    if (requested < 0) {
        return 0;
    }
    if (requested > 100) {
        return 100;
    }

    return requested;
}

class Volume {
private:
    int level_{30};

public:
    Volume() = default;

    explicit Volume(int initialLevel)
        : level_{boundedLevel(initialLevel)}
    {
    }

    int level() const
    {
        return level_;
    }

    void setLevel(int requested)
    {
        level_ = boundedLevel(requested);
    }
};

int main()
{
    Volume normal{};
    Volume loud{135};

    std::cout << normal.level() << ' ' << loud.level() << '\n';

    loud.setLevel(42);
    normal.setLevel(-5);

    std::cout << normal.level() << ' ' << loud.level() << '\n';
}
```

예상 출력:

```text
30 100
0 42
```

### 코드를 따라 읽기

1. `boundedLevel`은 요청값을 0~100 범위로 보정하는 보통의 함수입니다. 작은 규칙을 함수 하나로 모아 생성자와 변경 함수가 함께 사용합니다.
2. `level_`은 객체마다 현재 음량을 보관합니다. 이름 끝의 밑줄은 멤버임을 구분하기 위한 작성 관례이지 C++의 특별한 문법이 아닙니다.
3. `Volume normal{};`은 인자 없이 객체를 만듭니다. 이 예제의 기본값은 30입니다.
4. `Volume loud{135};`은 정수 인자를 받는 생성자를 사용합니다. 보정한 100으로 멤버를 초기화합니다.
5. 두 번의 `setLevel` 호출에도 같은 보정 함수를 사용합니다. 생성할 때만 확인하고 이후 변경을 방치하지 않습니다.

정수 인자를 받는 생성자 앞의 `explicit`는 이 생성자를 통한 의도하지 않은 암시적 변환을 제한합니다. 여기서 사용하는 `Volume loud{135};`와 같은 직접 초기화는 허용됩니다. 변환의 세부 규칙은 뒤에서 다룹니다. [C++20 초안: 생성자를 통한 변환](https://timsong-cpp.github.io/cppwp/n4861/class.conv.ctor)

## 4. 초기화 목록과 생성자 본문은 다른 단계입니다

주예제의 생성자에서 콜론 다음 부분을 살펴보세요.

`Volume(int initialLevel) : level_{boundedLevel(initialLevel)}`

콜론 뒤의 `level_{...}`는 **멤버 초기화 목록**의 항목입니다. `level_`을 보정된 값으로 초기화합니다. 이어지는 빈 `{ }`는 생성자 본문입니다. 본문에 명령문이 없어도 멤버 초기화는 수행됩니다.

반면 본문 안에서 `level_ = ...;`를 실행한다면 이미 초기화 단계를 거친 멤버에 **대입**하는 것입니다. 초기화 목록의 `level_{값}`과 본문의 `level_ = 값;`는 같은 일을 다른 모양으로 쓴 것이 아닙니다. 주예제의 `setLevel`은 이미 만들어진 객체를 변경하므로 대입이 적절합니다.

이 구분은 나중에 const 멤버나 다른 클래스 타입의 멤버를 다룰 때도 중요합니다. 지금은 “멤버를 먼저 초기화하고, 그 다음 생성자 본문이 실행된다”는 순서를 기억하세요. [C++20 초안: 멤버 초기화](https://timsong-cpp.github.io/cppwp/n4861/class.base.init)

### 선언 순서가 실제 초기화 순서입니다

이 수업처럼 상속을 사용하지 않는 클래스에서는 비정적 데이터 멤버가 **클래스에 선언된 순서**로 초기화됩니다. 초기화 목록을 적은 순서로 바뀌지 않습니다. 읽는 사람도 순서를 정확히 이해하도록 초기화 목록을 선언 순서에 맞춰 작성하세요.

```cpp
#include <iostream>

class MarkerPair {
private:
    int first_;
    int second_;

public:
    MarkerPair()
        : first_{7}, second_{first_ + 1}
    {
        std::cout << "body: " << first_ << ' ' << second_ << '\n';
    }
};

int main()
{
    MarkerPair markers{};

    std::cout << "ready\n";
}
```

예상 출력:

```text
body: 7 8
ready
```

`first_`를 먼저 선언했으므로 7로 초기화한 다음, 그 값을 사용해 `second_`를 8로 초기화합니다. 두 멤버의 초기화가 끝나면 생성자 본문에서 값을 출력합니다. 생성자가 끝난 뒤 `main`의 다음 문장이 실행됩니다.

다음은 이 예제만을 위한 **정확한 실행 순서 설명**입니다. 앞의 AI 개념 그림과 달리 언어 규칙을 순서대로 적었습니다.

1. `first_`를 7로 초기화
2. `second_`를 `first_ + 1`, 즉 8로 초기화
3. 생성자 본문에서 `body: 7 8` 출력
4. 객체 선언 다음 문장에서 `ready` 출력

초기화 목록의 항목만 뒤집어 쓰더라도 멤버 선언 순서는 바뀌지 않습니다. 특히 아직 초기화되지 않은 멤버의 값을 다른 멤버의 초기화에 사용하지 않도록 주의하세요. 그런 잘못된 프로그램을 실행해 나온 숫자로 규칙을 추측하지 않습니다.

## 5. 기본 멤버 초기화와 기본 생성자

`int level_{30};`의 `{30}`은 **기본 멤버 초기화(default member initializer)**입니다. 생성자의 초기화 목록이 그 멤버를 따로 지정하지 않을 때 사용할 값입니다. 정수 인자를 받는 `Volume` 생성자는 `level_{boundedLevel(initialLevel)}`를 직접 지정하므로, 그 생성에서는 기본 멤버 초기화의 30을 사용하지 않습니다. 30을 넣었다가 다시 덮어쓰는 과정도 아닙니다. [C++20 초안: 기본 멤버 초기화 적용](https://timsong-cpp.github.io/cppwp/n4861/class.base.init)

**기본 생성자(default constructor)**는 인자 없이 호출할 수 있는 생성자입니다. 매개변수가 전혀 없는 경우뿐 아니라 모든 매개변수에 기본 인자가 있는 경우도 해당합니다.

사용자가 생성자를 하나도 선언하지 않으면 컴파일러가 기본 생성자를 암시적으로 선언합니다. 그러나 “선언된다”가 모든 클래스에서 반드시 호출 가능하다는 뜻은 아닙니다. 멤버 구성에 따라 사용할 수 없게 되는 경우도 있습니다. 현재 예제처럼 `int` 멤버를 명시적으로 초기화하는 단순한 클래스부터 살펴보겠습니다. [C++20 초안: 기본 생성자](https://timsong-cpp.github.io/cppwp/n4861/class.default.ctor)

`Volume`에는 정수 인자를 받는 생성자를 우리가 선언했습니다. 그러므로 인자 없는 생성자가 저절로 추가된다고 기대하면 안 됩니다. 주예제는 `Volume() = default;`를 명시해 기본 생성자를 요청했습니다. 이 기본 생성자는 `level_{30}`을 사용합니다. `= default`는 별도의 값 0을 강제로 넣는 명령이 아닙니다.

다음 코드는 **의도적으로 컴파일에 실패**합니다.

```cpp
class Ticket {
private:
    int number_;

public:
    explicit Ticket(int number)
        : number_{number}
    {
    }

    int number() const
    {
        return number_;
    }
};

int main()
{
    Ticket ticket{}; // Intentional: no constructor accepts zero arguments.
}
```

`Ticket`에는 정수 하나를 받는 생성자만 있고, 인자 없이 호출할 수 있는 생성자가 없습니다. 생성자에 필요한 값을 주어 `Ticket ticket{7};`처럼 만들거나, 프로그램의 의미에 맞는 기본 생성자를 별도로 설계해야 합니다. 무조건 기본 생성자를 추가하는 것이 정답은 아닙니다. 예를 들어 번호 없는 입장권을 허용하지 않는 프로그램이라면 기본 생성을 막는 편이 자연스럽습니다.

## 6. 규칙을 지키는 변경 경로까지 설계하기

생성자는 출발점을 만들지만, 이후의 모든 변경을 대신 검사하지는 않습니다. 주예제는 다음 두 경로가 같은 규칙을 적용하도록 구성했습니다.

| 경로 | 요청 | 결과 |
|---|---:|---:|
| 생성 | -1 | 0으로 시작 |
| 생성 | 100 | 100으로 시작 |
| 생성 | 101 | 100으로 시작 |
| 변경 | 42 | 42로 변경 |
| 변경 | -5 | 0으로 변경 |

위 숫자는 성능 측정값이 아니라, 우리가 정한 보정 정책의 입력·결과 사례입니다.

데이터를 private로 만들었다는 사실만 검사하고 끝내지 마세요. “외부에서 사용할 각 함수가 어떤 값을 받아 어떤 상태를 남기는가?”까지 확인해야 합니다. 또한 기본값 30, 최솟값 0, 최댓값 100은 요구 사항이 바뀌면 재검토할 설계 선택입니다.

## 7. 연습문제

### 문제 1 — 경계에서 예상하기

`Volume` 객체를 각각 -1, 0, 100, 101로 만들어 조회하면 어떤 값이 나오는지 적어 보세요. 그 다음 하나의 객체에 같은 네 값을 차례대로 `setLevel`로 전달했을 때의 결과도 적어 보세요.

### 문제 2 — 접근 제어의 책임

“`level_`이 private이므로 어떤 public 함수를 추가해도 0~100 범위를 벗어날 수 없다.”라는 설명이 맞는지 판단하고 이유를 적어 보세요.

### 문제 3 — 초기화 순서

`MarkerPair`에서 `first_`와 `second_`의 선언 순서는 그대로 두고 초기화 목록의 두 항목만 뒤집으면 실제 초기화 순서가 바뀔까요? 읽기 쉬운 작성 방식도 함께 설명해 보세요. 일부러 순서를 뒤집은 코드를 실행할 필요는 없습니다.

### 문제 4 — 경계 검사를 실행으로 확인하기

주예제의 클래스와 `boundedLevel`은 그대로 두고 `main`만 바꾸어 문제 1을 출력으로 확인해 보세요. 예상 출력은 두 줄 모두 `0 0 100 100`입니다. 객체 선언, 변경, 출력의 의미 단위 사이에 빈 줄을 넣어 보세요.

### 문제 5 — 기본 상태를 허용할 것인가?

번호가 있어야만 의미가 있는 `Ticket`을 만들고 싶습니다. `Ticket ticket{};`을 컴파일할 수 있게 만들기 위해 무조건 `Ticket() = default;`를 추가하는 것이 적절한지 설명해 보세요. 번호를 0으로 놓으면 모든 프로그램에서 유효하다고 말할 수 있을까요?

## 8. 해설

### 해설 1

생성과 변경 모두 `0, 0, 100, 100`입니다. 최솟값과 최댓값 자체는 유지하고, 범위를 벗어난 값만 가까운 끝값으로 보정합니다.

### 해설 2

틀렸습니다. 멤버 함수는 private 멤버에 접근할 수 있습니다. 새 public 함수가 검사 없이 값을 대입하면 불변식이 깨질 수 있습니다. 접근 제어는 변경 경로를 줄이는 데 도움을 주며, 그 경로의 올바른 구현은 작성자의 책임입니다.

### 해설 3

바뀌지 않습니다. 실제 순서는 데이터 멤버의 선언 순서입니다. 초기화 목록도 `first_`, `second_` 순으로 적으면 실제 순서와 읽는 순서가 일치합니다.

### 해설 4

다음은 교체할 `main`입니다. 앞에서 작성한 `boundedLevel`과 `Volume` 정의 뒤에 둡니다. 이 코드 조각만으로는 완전한 프로그램이 아닙니다.

```cpp
int main()
{
    Volume below{-1};
    Volume lowest{0};
    Volume highest{100};
    Volume above{101};

    std::cout << below.level() << ' ' << lowest.level() << ' '
              << highest.level() << ' ' << above.level() << '\n';

    Volume changed{};

    changed.setLevel(-1);
    std::cout << changed.level() << ' ';

    changed.setLevel(0);
    std::cout << changed.level() << ' ';

    changed.setLevel(100);
    std::cout << changed.level() << ' ';

    changed.setLevel(101);
    std::cout << changed.level() << '\n';
}
```

예상 출력:

```text
0 0 100 100
0 0 100 100
```

### 해설 5

적절하다고 단정할 수 없습니다. 객체를 사용하려면 번호가 반드시 필요하다면 인자 없이 만드는 것을 허용하지 않는 설계가 더 명확합니다. 정수 0이 언어 차원에서 표현 가능한 값이라는 사실과, 입장권 번호로 유효하다는 사실은 다릅니다. 기본 생성자를 추가할지와 기본값을 무엇으로 정할지는 프로그램의 규칙에 따라 결정합니다.

## 정리

- 생성자는 객체의 초기 상태를 마련합니다. 무엇을 유효한 상태로 볼지는 프로그램에서 정합니다.
- 멤버 초기화 목록은 생성자 본문보다 먼저 적용되며, 비정적 데이터 멤버는 선언 순서로 초기화됩니다.
- 기본 멤버 초기화는 해당 멤버를 초기화 목록에서 지정하지 않았을 때 사용합니다.
- 생성자를 직접 선언했다면 인자 없는 생성자가 자동으로 추가된다고 가정하지 않습니다.
- private 데이터와 올바른 public 함수가 함께 있어야 정한 규칙을 유지할 수 있습니다.

다음 수업에서는 조회 함수 끝에 붙였던 `const`를 본격적으로 다룹니다. 객체를 바꾸지 않는 사용 방법을 타입과 함수 선언에 어떻게 드러내는지 살펴보겠습니다.
