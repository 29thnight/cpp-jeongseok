# 집필 상태와 예약 실행 절차

## 현재 범위

본편 53수업과 선택 심화 4수업을 추적한다. `state.json`이 상태의 원본이며 `PROGRESS.md`는 재생성 가능한 표다. 수업 목표는 최초의 잠정 목표다. A 단계에서 관찰 가능한 목표 1~3개로 구체화한다. 기존 소개 글은 실제 내용 대조 후 별도 참고 읽기로 연결했으며 57수업의 완료 실적에 넣지 않았다. 사이트의 기존 큰 주제별 목차와 이 수업별 제작 목록은 서로 다른 단위다.

이 변경은 예약 실행기, 자동 집필기, 자동 배포기가 아니다. `next`는 후보만 제안한다. 실행 주기, 비공개 보관 위치와 실제 집필 작업자는 별도로 관리한다. 실제 집필·검증 여부는 수업별 상태와 완료 증거로 확인한다.

## 상태와 단계

| 상태 | 의미 | 자동 재개 후보 |
|---|---|---|
| not_started / 미착수 | 아직 집필 작업을 시작하지 않음 | 선행 충족 시 |
| writing / 집필중 | 비공개 영속 보관소에서 작은 작업 진행 | 예 |
| example_validation / 예제검증 | C++20 예제의 실제 빌드·실행 검증 중 | 예 |
| awaiting_review / 검수대기 | 기술·편집 검사를 마친 검토 묶음, 사람 검토 대기 | 아니오 |
| needs_revision / 수정필요 | 검토 의견을 반영해야 함 | 예 |
| ready_to_publish / 게시준비 | 검토가 승인된 비공개 완성본 | 아니오 |
| published / 게시완료 | 별도 공개 승인 후 실제 게시와 링크 확인까지 완료 | 아니오 |
| blocked / 차단 | 보관소·도구·선행·허가 등의 문제로 진행 불가 | 아니오 |

단계는 A 목표 → B 사실·개념 검토 → C 새 예제와 테스트 → D 본문·그림 → E 연습과 해설 → F 기술·편집 검수 → G 검토 묶음이다. 한 체크포인트에서 앞으로 한 단계만 이동할 수 있다. 수정 시 A~C 단계로 돌아가 기존 증거를 비우고 검토 승인 결과를 무효화한다. 목표 변경·단계 후퇴·수정필요 전환 시 도구가 이 초기화를 요구한다. A 안에서도 여러 체크포인트를 남길 수 있다. 상태는 단계와 별개다. 집필중이라고 예제 검증이나 게시가 완료된 것은 아니다.

선행 수업의 `ready_to_publish` 또는 `published`를 집필 선행 충족으로 본다. 이는 검수된 비공개 수업만 있어도 다음 수업을 만들 수 있다는 뜻이다. 독자에게 공개된 선행 자료인지 여부는 게시 전 별도로 확인한다. 선택 수업은 본편의 선행이 될 수 없다. `next`는 진행중/수정필요를 먼저 고르고, 같은 우선순위에서는 목록 순서를 따른다. 검토 대기와 차단 항목을 자동으로 다시 시작하지 않는다. 후보가 없으면 원인을 보고하고 멈춘다.

## 명령

Python 3.10 이상, 추가 패키지 없음. 저장소 루트에서 실행한다.

```sh
python3 scripts/curriculum.py validate
python3 scripts/curriculum.py next
python3 scripts/curriculum.py next --include-optional
python3 scripts/curriculum.py render
python3 scripts/curriculum.py render --check
python3 -m unittest discover -s tests -v
```

`next`의 `state_sha256`은 읽은 상태의 원문 바이트 해시다. 변경 전 해시와 재실행에도 유지되는 체크포인트 ID를 사용한다. 체크포인트 ID는 비밀이나 사용자 정보 없이 작업 실행 번호와 단계 번호로 만든다. 한 ID는 한 변경에만 쓴다. 같은 ID와 같은 변경은 성공을 반복 반환하며 기록을 중복 추가하지 않는다. ID가 같은데 내용이 다르면 거부한다.

다음은 형식 예시이며 실제 집필 시작을 의미하지 않는다. 비공개 영속 저장이 먼저 확인되어야 `private_durable`로 기록한다.

```json
{
  "status": "writing",
  "draft": "private_durable",
  "next_action": "학습 목표를 검토한다."
}
```

패치 파일은 공개 저장소 밖에서 준비한다. 명령의 대문자 인자는 실제 값으로 교체한다.

```sh
python3 scripts/curriculum.py checkpoint --expected-sha CURRENT_SHA256 --run-id RUN_STAGE_ID --lesson 00-1 --patch PATCH_FILE
python3 scripts/curriculum.py render
```

체크포인트는 상태 파일만 바꾼다. 커밋·푸시·배포는 하지 않는다. 변경 내용에 모르는 필드, 비공개 위치, 임의 URL, 코드 블록을 넣으면 안 된다. 저장 파일을 직접 편집해 검증을 우회하지 않는다.

## 서로 다른 실행 환경에서도 재개하기

1. 최초 예약 전 사용자 소유 비공개 영속 보관 위치와 접근 권한을 정한다. 그곳에 수업 ID별 초안, 새 예제, 테스트, 상세 검토 증거와 체크포인트 색인을 보관한다. 실제 위치·원본 대응·개인 파일 ID는 공개 상태나 로그에 기록하지 않는다. 로컬 임시 폴더와 공개 저장소의 gitignore만으로 비공개 보관을 대신하지 않는다. 다음 실행에서 실제 읽을 수 있는지 확인하기 전에는 시작하지 않는다.
2. 실행기에는 동시 집필 1개 제한을 건다. 시작할 때 원격 main의 정확한 커밋과 상태를 새로 읽는다. `validate`, `next`를 실행한다. 진행중 초안이 있으면 비공개 색인과 마지막 체크포인트를 읽는다. 상태가 `private_durable`인데 보관물을 찾을 수 없으면 새로 덮어쓰지 말고 차단·보고한다.
3. 한 번에 한 수업의 한 작은 작업만 처리한다. 외부 보관소에 수업 ID와 체크포인트 ID로 찾을 수 있는 불변 스냅샷을 먼저 저장하고, 저장 후 다시 읽어 확인한다. 그 후 공개 가능한 최소 요약만 패치로 만든다. 같은 체크포인트 스냅샷이 이미 있으면 재사용·대조한다. 기존 초안을 처음부터 다시 생성하지 않는다.
4. `checkpoint`에 읽은 SHA와 체크포인트 ID를 전달한다. 로컬 잠금과 원자적 파일 교체가 같은 환경의 동시 변경을 막는다. 상태 검증·표 생성·테스트 후 승인된 상태 관리 파일만 커밋한다. 원격 커밋이 시작 때의 head와 같을 때만 정상 fast-forward 또는 API expected-head 비교 방식으로 반영한다. 강제 푸시는 하지 않는다. 원격이 달라졌다면 새 상태와 비공개 스냅샷을 대조해 조정한다. 로컬 SHA 검사만으로 다른 컴퓨터의 변경을 보호할 수는 없다.
5. 원격의 커밋과 체크포인트 ID를 다시 확인한 뒤 해당 작업이 영속화됐다고 보고한다. 임시 컴퓨터가 종료돼도 다음 실행은 원격 상태와 비공개 보관물을 기준으로 재개한다. 저장 중 중단되면 비공개 스냅샷이 상태보다 앞설 수 있으므로 먼저 조정한다. 완료 보고만 보고 상태를 추정하지 않는다.
6. 오류나 권한 부족은 `blocked`와 공개 가능한 이유, 다음 행동으로 남긴다. 원본 이름·경로·링크가 섞인 예외 로그는 공개하지 않는다. 사람 검토가 필요하면 `awaiting_review`에서 멈춘다. 이 조건을 충족하지 않는 실행기에 예약을 연결하지 않는다.

잠금 파일이 남으면 기존 프로세스가 중단됐고 저장 파일이 유효한지 확인한 후 사람이 잠금만 회수한다. 시간 경과나 잠금 만료는 작업 완료 증거가 아니다. 이 도구에는 분산 잠금이나 자동 lease 회수가 없다. 실행기의 단일 작업 보장과 원격 head 비교를 함께 사용해야 한다.

## 완료 증거

증거 항목은 `result`, 시간대 포함 `checked_at`, 민감정보 없는 한 줄 `summary`로 제한한다. 상세 로그·초안 해시·컴파일러 버전·명령·예상과 실제 출력·검토자·승인 메시지·대상 판본은 비공개 영속 보관소에서 해당 체크포인트로 연결한다. 공개 요약은 검증을 실제 수행한 사람이 작성한다. 스키마 검증 자체는 컴파일이나 검토를 대신하지 않는다.

- `examples`: C++20 기준 정확한 컴파일러와 버전, 표준 옵션, 빌드 명령을 기록하고 새 예제의 정상·경계·실패 경로를 실제 실행한다. 의도된 컴파일 실패는 예상 진단을 확인한다. 지원 환경의 경고·sanitizer 결과와 지원하지 않는 범위를 기록한다. 실행 코드 없는 개념 수업만 근거를 적어 `not_applicable` 허용
- `technical`: 목표·선행 일치, 표준 버전, 수명·소유권·예외·스레드 종료 가정, 연습과 해설 정확성을 확인
- `editorial`: 새로 쓴 문장·그림인지, 문제→예측→설명→실습 흐름과 용어·중복을 확인
- `links`: 내부 링크와 앵커, 공개 예정 예제 경로, 사이트 빌드와 테스트를 확인
- `privacy`: 공개 예정 diff 전체의 코드·이미지·문장·메타데이터·링크·파일명·경로를 검수하여 비공개 자료 유출과 불필요한 인용이 없는지 확인. 정규식 검사는 보조일 뿐 의미상 복제를 판단하지 못함
- `approval`: 해당 수업과 판본, 공개할 본문·예제·그림, 공개 저장소와 사이트에 대한 별도 명시 승인을 확인
- `publication`: 승인된 파일을 게시한 정확한 커밋과 실서비스 URL·내용·선행 링크를 확인

D 이후는 예제 검증을 요구한다. 검수대기는 모든 품질 검사 후 G 단계에서만 가능하다. 게시준비는 사람의 검토 승인까지 요구한다. 게시완료는 별도 공개 승인과 배포 확인 증거 및 존재하는 공개 파일 경로까지 요구한다. JSON의 승인 필드를 채우는 행위가 사용자 승인을 만들지는 않는다.

본문이나 예제를 바꾸면 그 영향을 받는 기존 검증과 공개 승인을 재사용하지 않는다. 수정필요로 되돌아가 관련 증거를 삭제하고 다시 검사한다. 게시된 문서의 수정 역시 별도 공개 범위를 확인한다.

## 공개 안전 경계

이 공개 저장소에는 수업의 공개 가능한 계획·상태·요약만 둔다. 원본 자료의 텍스트·코드·이미지·링크·파일명·폴더 경로, 비공개 초안 본문과 위치, 비공개 파일 ID를 넣지 않는다. 검토 전 초안은 브랜치나 PR에도 올리지 않는다. 공개 브랜치도 비공개 보관소가 아니다.

집필·검토 준비 승인은 공개 배포 승인이 아니다. 게시준비까지의 예약 작업은 `content/`, `assets/`, `docs/`에 수업 본문이나 이미지를 생성하거나 커밋하지 않는다. 공개 승인 전에는 허용 목록인 `curriculum/state.json`과 `curriculum/PROGRESS.md`의 상태 변경만 대상으로 삼는다. 비공개 파일을 포함할 수 있는 `git add .`는 사용하지 않는다.

현재 사이트 빌더는 `state.json`을 수업 본문으로 게시하지 않는다. 새 수업의 공개는 별도 승인 이후 사이트 게시 지원, 빌드·테스트와 실제 배포 검증을 거치는 별도 작업이다. 커밋 author와 committer는 저장소 소유자 29thnight만 사용하며 공동 작성자 트레일러를 추가하지 않는다.
