입력 검증, 경계값, 반복되는 작업 정리

조건문과 반복문을 배웠다면 이제 여러 문법을 하나의 프로그램 안에서 연결해 볼 차례입니다. 이번에는 수량을 입력받아 금액을 누적하는 작은 주문 계산기를 만듭니다. 목표는 기능을 많이 넣는 것이 아닙니다. 입력이 예상과 달라도, 정한 규칙을 지키면서 끝까지 동작하게 만드는 것입니다.

이 수업을 마치면 정수를 읽지 못한 경우와 읽은 값이 허용 범위를 벗어난 경우를 구분할 수 있습니다. 입력의 끝에서 반복을 종료하고, 합계를 바꾸기 전에 한도를 검사할 수 있습니다. 정상 입력만 시험하는 대신 경계값과 잘못된 입력으로 프로그램의 약속을 확인해 보겠습니다.

앞 수업의 변수, 산술 연산, if, while, break, continue를 사용합니다. 함수로 나누는 방법은 다음 수업에서 다룹니다. 여기서는 main 안의 반복 한 곳에 입력과 검사를 모읍니다.

1. 코드를 쓰기 전에 약속부터 정합니다

상품 한 개의 가격은 100이고, 한 번에 주문할 수 있는 수량은 1부터 9까지입니다. 0을 입력하면 종료합니다. 합계는 2000을 넘을 수 없습니다. 주문 하나를 추가하면 한도를 넘는 경우에는 그 주문 전체를 거절합니다. 남은 금액만큼 일부를 자동 주문하지 않습니다.

정수로 읽을 수 없는 입력을 만나면 오류를 알리고 그 줄의 남은 내용을 버린 뒤 다시 입력받습니다. 더 읽을 입력이 없거나 입력 스트림에 심각한 오류가 생겼다면 종료합니다. 종료할 때는 지금까지 받아들인 주문의 합계를 출력합니다.

중요한 한계도 먼저 정하겠습니다. 이번 예제의 정수 입력은 한 줄 전체가 정수인지 검사하지 않습니다. std::cin >> quantity는 앞부분에서 정수로 해석할 수 있는 문자를 읽습니다. 따라서 2abc를 입력하면 먼저 2를 읽을 수 있습니다. 뒤의 abc는 다음 입력 시도에서 문제가 됩니다. 문자열 전체를 검사하는 엄격한 입력기는 문자열을 배운 뒤 별도로 만들겠습니다.

2. 정수로 읽는 데 성공했는지 확인합니다

std::cin은 표준 입력 스트림입니다. >> 연산자로 int 변수에 입력하면 입력 문자들을 정수로 해석하려고 시도합니다. 앞에 있는 공백이나 줄바꿈은 일반적인 정수 입력에서 건너뜁니다. 입력은 반드시 키보드에서만 오는 것은 아닙니다. 파일이나 다른 프로그램이 제공할 수도 있습니다.

다음 코드는 정수를 두 차례 읽고, 각 추출이 성공했는지 확인하는 독립 실행 예제입니다.

#include <iostream>

int main() {
    int first = 0;
    int second = 0;

    if (std::cin >> first) {
        std::cout << "First integer: " << first << '\n';
    } else {
        std::cout << "First extraction failed.\n";
        return 0;
    }

    if (std::cin >> second) {
        std::cout << "Second integer: " << second << '\n';
    } else {
        std::cout << "Second extraction failed.\n";
    }
    return 0;
}

7 8을 입력하면 두 추출 모두 성공합니다. 7만 입력하고 엔터를 누르면 첫 추출은 성공하고 두 번째 정수를 기다립니다. abc를 주면 첫 정수 추출부터 실패합니다. 실패한 경우에는 입력 대상 변수의 값을 유효한 주문으로 사용하면 안 됩니다. 변수를 0으로 초기화했더라도 실패를 0 주문이나 종료 요청으로 취급하지 않습니다. 먼저 성공 여부를 확인해야 합니다.

!(std::cin >> quantity)는 입력 연산 결과인 스트림을 성공·실패 판단에 사용한 뒤 부정합니다. 조건이 참이면 실패 경로입니다. 여기서 스트림의 모든 상태를 외울 필요는 없습니다. 값을 읽는 연산과 성공 여부 확인이 연결되어 있다는 점을 익혀 보세요.

3. 입력 실패와 범위 오류는 다릅니다

abc는 int로 읽는 데 실패합니다. 반면 -1이나 10은 int로 읽는 데 성공하지만 주문 수량 1~9에는 맞지 않습니다. 전자는 입력 해석 문제이고, 후자는 프로그램이 정한 업무 규칙 위반입니다. 처리 위치를 나누면 이유와 동작이 분명해집니다.

정수 추출에 실패한 스트림에서는 실패 상태를 그대로 둔 채 같은 추출을 반복해도 정상 입력 처리가 이어지지 않습니다. 이 예제는 복구 가능한 실패에서 두 작업을 합니다.

첫째, std::cin.clear()로 오류 상태를 해제합니다. 이것만으로 잘못된 문자들이 없어지지는 않습니다. 둘째, std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n')으로 현재 줄의 나머지와 줄바꿈 문자를 버립니다. 입력 상태를 먼저 해제한 다음 문자를 버리는 순서입니다.

<limits>와 numeric_limits는 이 줄에서 쓸 표준 도구로 받아들여도 충분합니다. 긴 형식의 뜻은 ‘streamsize가 표현하는 최대 개수’를 지정한다는 것입니다. 이 특별한 최대값을 사용하면 ignore의 개수 제한이 비활성화되어 줄바꿈이나 입력 끝까지 버릴 수 있습니다. 템플릿 문법 자체는 뒤에서 배웁니다.

이 정책은 abc 3처럼 한 줄에 잘못된 문자와 정상 숫자가 함께 있으면 3도 버립니다. 잘못된 부분만 골라 복구하는 기능은 아닙니다. 사용자에게 ‘줄의 나머지를 버렸다’고 안내하는 이유입니다.

입력 끝인 EOF는 다시 물어볼 입력이 없다는 뜻입니다. clear만 하며 무한히 재시도하지 않습니다. bad()로 확인하는 심각한 스트림 오류도 여기서는 복구를 시도하지 않고 끝냅니다. EOF를 키보드로 보내는 방법은 터미널 환경마다 다르므로, 실습에서는 0 종료를 우선 사용하고 자동 시험에서는 빈 입력이나 입력 파일의 끝으로 EOF를 확인합니다.

4. 완성 프로그램

아래 내용을 하나의 .cpp 파일로 저장합니다. 출력 문구는 환경별 한글 콘솔 인코딩 문제를 줄이기 위해 영문으로 작성했습니다. 프로그램의 규칙과 입력값은 동일합니다.

#include <iostream>
#include <limits>

int main() {
    const int price = 100;
    const int totalLimit = 2000;
    int total = 0;

    while (true) {
        std::cout << "Quantity (1-9, 0 to finish):\n";
        int quantity = 0;

        if (!(std::cin >> quantity)) {
            // A broken stream or end of input cannot be repaired by asking again.
            if (std::cin.bad()) {
                std::cout << "Input stream error.\n";
                break;
            }
            if (std::cin.eof()) {
                std::cout << "End of input.\n";
                break;
            }

            // Clear failbit before discarding the remainder of this line.
            std::cin.clear();
            std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
            std::cout << "Invalid integer; discarded the rest of this line.\n";
            continue;
        }

        if (quantity == 0) {
            break;
        }
        if (quantity < 1 || quantity > 9) {
            std::cout << "Quantity must be 1-9.\n";
            continue;
        }

        // quantity is now 1-9, so amount is safely bounded by 900.
        const int amount = quantity * price;
        // total stays in 0-2000. Compare before adding to avoid overflow.
        if (amount > totalLimit - total) {
            std::cout << "Total limit exceeded; order not added.\n";
            continue;
        }
        total += amount;
        std::cout << "Added " << amount << "; total " << total << ".\n";
    }

    std::cout << "Final total: " << total << ".\n";
    return 0;
}

이 예제에서 '\n'은 출력의 줄을 바꿉니다. Hello World에서 사용한 std::endl은 줄바꿈과 스트림 flush를 함께 수행합니다. 여기서는 매 출력마다 명시적으로 flush할 필요가 없어 줄바꿈 문자를 사용했습니다. 기본 설정의 std::cin은 std::cout과 연결되어 있어 입력을 읽기 전 필요한 출력 flush가 이루어집니다.

5. 흐름을 한 갈래씩 따라갑니다

반복 시작에서는 수량을 입력받습니다. 입력 실패라면 bad, EOF를 차례로 확인하고 종료하거나, 복구한 뒤 continue로 다음 반복으로 이동합니다. 성공했다면 0 종료 요청을 먼저 확인합니다. 그 뒤에 1~9 범위를 검사합니다. 0도 주문 범위에는 없으므로 종료 확인을 범위 검사보다 먼저 둔 것입니다.

수량 검사를 통과한 뒤에야 amount를 계산합니다. 한도까지 통과하면 total을 한 번 갱신합니다. 거절한 입력이 합계에 영향을 주지 않도록, 갱신을 가장 뒤에 둡니다. 여러 갈래에 total 갱신을 흩어 두지 않는 것이 핵심입니다.

예를 들어 9 9 3 2 0을 입력하면 다음처럼 동작합니다.

  • 9: 900을 추가하고 합계는 900입니다
  • 9: 900을 추가하고 합계는 1800입니다
  • 3: 추가 금액 300이 남은 한도 200보다 크므로 거절합니다. 합계는 1800입니다
  • 2: 200을 추가하여 합계가 정확히 2000이 됩니다
  • 0: 종료하며 최종 합계 2000을 출력합니다

공백과 줄바꿈으로 수량을 나눌 수 있으므로 이 입력을 한 줄에 적어도 됩니다. 다만 입력 해석에 실패하면 현재 줄의 나머지를 버리는 정책이 적용됩니다.

6. 더한 뒤 검사하지 않는 이유

amount > totalLimit - total은 ‘추가하려는 금액이 남은 한도보다 큰가’를 묻습니다. 검사 후에 total += amount를 실행합니다. 어떤 숫자를 쓰든 뺄셈 방식이 무조건 안전하다는 뜻은 아닙니다. 여기에는 앞에서 만든 범위 보장이 필요합니다.

반복이 시작할 때 합계는 0 이상 2000 이하입니다. 처음에는 0이므로 성립합니다. 수량 검사를 통과하면 quantity는 1부터 9까지이고 amount는 100부터 900까지입니다. totalLimit - total은 0~2000입니다. 추가가 허용되는 경우에만 합계를 바꾸므로 바뀐 합계도 2000 이하입니다. 거절하거나 종료할 때는 바꾸지 않습니다. 이렇게 계속 유지되는 조건을 불변식이라고 부릅니다.

이 상수 범위에서는 계산값이 C++의 최소 int 범위 안에 있습니다. 가격이나 한도를 매우 큰 값으로 바꾸면 수량 곱셈부터 다시 검토해야 합니다. 이번 예제가 임의의 큰 정수를 안전하게 계산하는 범용 계산기는 아닙니다. 부호 있는 정수의 표현 범위를 넘는 계산은 뒤늦게 결과를 검사해서 해결할 수 없습니다.

7. 경계값으로 약속을 시험합니다

정상 입력 3 한 번만으로는 충분하지 않습니다. 범위의 바로 아래, 양 끝, 바로 위와 종료 입력을 함께 확인해 보세요.

  • -1, 1, 9, 10: 수량 경계입니다. -1과 10은 거절하고 1과 9는 받아들입니다
  • 0: 합계를 더하지 않고 종료합니다
  • 9 9 2 0: 한도에 정확히 도달하여 2000이 됩니다
  • 9 9 3 0: 마지막 주문을 거절하여 1800이 됩니다
  • abc 뒤 줄바꿈, 다음 줄에 2 0: 첫 줄을 버린 뒤 정상 입력을 이어 받아 200이 됩니다
  • 매우 긴 숫자: int에 담을 수 없는 정수 추출 실패입니다. 실패값은 합계에 쓰지 않습니다
  • 빈 입력의 끝: 반복 출력만 계속하지 않고 최종 합계 0으로 끝납니다

실제로 실행하기 전에 예상 합계를 먼저 적어 보세요. 실행 결과가 다르면 코드를 무작정 고치기보다 ‘어느 검사에서 예상과 갈라졌는가’를 찾습니다.

8. 2abc가 2로 처리되는 이유

이 예제의 한계를 직접 확인해 보겠습니다. 2abc 뒤에 줄바꿈을 넣고 다음 줄에 0을 입력하면 첫 추출은 2를 받아들여 200을 추가합니다. 다음 반복은 남은 a에서 실패하고 줄의 나머지를 버립니다. 마지막으로 0을 읽어 종료합니다. 2.5도 먼저 2를 읽은 뒤 소수점에서 실패하는 경로입니다.

12abc라면 먼저 12를 읽지만 범위 검사에서 거절합니다. 다음 추출에서 abc 때문에 실패합니다. 0abc는 0을 읽은 즉시 종료하므로 뒤의 abc를 검사하지 않습니다. 성공 여부와 업무 범위만 검사하면 입력 줄 전체의 적합성까지 보장된다고 생각하면 안 됩니다.

정상 정수 뒤에 마지막 줄바꿈 없이 입력이 끝나도 그 정수는 처리될 수 있습니다. EOF 상태만 보고 이미 성공한 값을 버리지 않도록, 코드는 추출 실패 경로 안에서 EOF를 확인합니다. 반대로 너무 큰 숫자를 읽다가 입력 끝까지 도달해 추출이 실패하면 이 프로그램에서는 EOF 안내가 우선합니다. 어느 경우든 실패한 추출로 주문을 추가하지는 않습니다.

한 줄 전체가 오직 정수 하나인지 엄격히 검사하려면 먼저 줄 전체를 문자열로 받아 남은 문자가 있는지까지 확인하는 설계가 필요합니다. 지금은 그 기능을 구현했다고 간주하지 않습니다. 사용하는 도구가 어디까지 보장하는지 아는 것도 입력 검증의 일부입니다.

9. 반복되는 작업을 정리한다는 것

이 프로그램은 입력 안내, 추출, 오류 처리, 범위 검사, 합계 갱신을 하나의 while에 모았습니다. 주문을 세 번 받으려고 같은 코드를 세 번 복사하지 않습니다. 오류가 발생해도 같은 입력 경로로 돌아오므로 정책을 고칠 위치가 분명합니다.

여기서 continue는 ‘이번 입력은 여기서 끝내고 다시 받는다’, break는 ‘전체 주문 입력을 끝낸다’는 역할을 맡습니다. 복잡한 기능을 더하기 전에 이 두 동작을 구분할 수 있어야 합니다. 다음 수업에서는 이 흐름에서 의미 있는 작업을 함수로 나누는 방법을 배웁니다.

  3. clear만 호출하고 ignore를 제거하면 abc 입력에서 어떤 문제가 생길까요?
  4. 한도 검사 전에 total += amount를 옮기면 9 9 3 0에서 어떤 약속을 어기나요?
  5. 2abc와 abc 2를 각각 한 줄에 입력한 뒤 다음 줄에 0을 입력합니다. 두 입력이 왜 다른 합계를 만드는지 설명해 보세요.
  6. 상품 가격을 150으로 바꾸고 한도는 2000으로 유지합니다. 9 4 1 0에서 각 주문의 채택 여부와 최종 합계를 예상하고, 코드를 바꿔 실행하여 확인해 보세요. 원래 가격의 시험 결과로 수정본까지 검증됐다고 판단하지 마세요.

11. 해설

  1. 1과 9를 받아들여 합계는 1000입니다. 10은 정수 추출에는 성공하지만 수량 범위 검사에서 거절됩니다. 0은 종료 요청입니다.
  2. 0은 1~9 범위 밖이므로 continue로 넘어갑니다. 종료 확인에 도달하지 못합니다. 정상적인 0 종료가 작동하지 않습니다.
  3. 실패 상태는 해제되지만 a가 입력에 남습니다. 다음 추출도 같은 a에서 실패합니다. 정상 입력을 기다리는 것처럼 보이면서 안내와 오류를 반복할 수 있습니다. 상태 해제와 잘못된 문자 제거는 다른 작업입니다.
  4. 기존의 남은 한도 비교식을 그대로 두고 더하기만 앞으로 옮기면 두 번째 9에서 합계가 1800이 된 뒤 900 > 200을 검사해 이미 더한 주문을 잘못 거절합니다. 세 번째 3에서는 합계가 2100까지 올라갑니다. 거절 안내만 출력하고 값을 되돌리지 않으면 ‘거절한 주문은 합계에 반영하지 않는다’는 규칙이 깨집니다. 갱신 전 검사를 유지하는 편이 단순합니다.
  5. 2abc는 먼저 2를 읽어 합계 200을 만듭니다. abc 2는 a에서 첫 추출이 실패하고 같은 줄의 2까지 버리므로 합계는 0입니다. 전체 줄을 한 번에 정수로 검증하는 방식이 아니기 때문입니다.
  6. 9개는 1350, 4개는 600이므로 합계는 1950입니다. 다음 1개는 150이고 남은 한도는 50이므로 거절합니다. 최종 합계는 1950입니다. quantity의 상한 9를 유지했으므로 amount의 상한은 1350으로 바뀝니다.

핵심 정리

입력에 성공했는지와 업무 규칙에 맞는지는 따로 확인합니다. 복구 가능한 오류에서는 상태를 해제하고 잘못된 입력을 제거합니다. 입력 끝은 종료 경로로 처리합니다. 합계는 조건을 통과한 뒤 한 곳에서 갱신하며, 정상·경계·오류 입력을 함께 시험합니다. 정수 접두사 추출을 엄격한 한 줄 검증으로 오해하지 않습니다.
