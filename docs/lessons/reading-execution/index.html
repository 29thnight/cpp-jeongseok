코드를 읽고 실행을 따라가기

코드는 읽었는데 어떤 결과가 나올지는 잘 모르겠다면, 어디부터 살펴보면 될까요? 우선 짧은 프로그램에서 지금 실행하는 문장과 지금까지 출력한 내용을 함께 적어 보겠습니다. 이번 수업에서는 새로운 문법을 많이 외우기보다, 예상한 결과를 실제 실행과 비교하는 방법을 익힙니다.

앞 수업에서 만든 콘솔 프로젝트를 그대로 사용해도 됩니다. 예제는 하나씩 main이 들어 있는 기존 파일의 내용과 교체해서 실행하세요. 여러 예제의 main을 같은 프로젝트에 한꺼번에 추가하지 않습니다.

이 수업을 마치면

  • 단순한 main 안의 출력 순서를 따라가며 결과를 먼저 적을 수 있습니다.
  • 편집기의 줄바꿈, C++의 문장, 화면의 줄바꿈을 구분할 수 있습니다.
  • 예상과 실제 결과가 다를 때 처음 어긋난 문장을 찾아 이유를 설명할 수 있습니다.

1 실행할 문장과 준비하는 부분

이 수업의 예제는 #include <iostream>, int main(), 중괄호로 묶인 본문을 공통으로 사용합니다. #include는 표준 입출력 기능을 사용하는 데 필요한 헤더를 포함하는 전처리 지시문입니다. 실행 중 화면에 무언가를 출력하는 문장은 아닙니다.

main은 이 콘솔 프로그램에서 살펴볼 실행의 시작점입니다. 정확히는 main에 들어오기 전에 실행 환경의 준비와 일부 초기화가 있을 수 있습니다. 지금 예제에는 그런 초기화를 직접 작성하지 않았으므로 main의 본문부터 따라가면 됩니다.

본문의 {와 }는 여러 문장을 하나의 블록으로 묶습니다. 아래처럼 분기나 반복이 없는 예제에서는 본문 안의 문장을 차례로 따라갑니다. 나중에 조건문과 반복문을 배우면 실행 경로가 달라질 수 있으므로, 모든 C++ 코드를 파일의 첫 줄부터 끝까지 무조건 실행한다고 외우지는 않습니다.

2 출력 결과를 먼저 적어 보기

다음 코드를 실행하기 전에 화면에 나올 문장을 순서대로 적어 보세요.

#include <iostream>

int main()
{
    std::cout << "Ready" << std::endl;
    std::cout << "Open" << std::endl;
    std::cout << "Close" << std::endl;
    return 0;
}

std::cout은 표준 출력 스트림 객체입니다. 이 예제의 <<는 오른쪽의 내용을 그 스트림에 출력하는 데 사용합니다. 큰따옴표로 묶은 "Ready"는 출력할 문자열입니다. 큰따옴표 자체는 화면에 나타나지 않습니다.

std::endl은 줄바꿈 문자를 넣고 스트림을 flush하는 스트림 조작 함수입니다. flush는 버퍼에 남은 출력을 연결된 출력 대상으로 전달하도록 요청하는 동작입니다. 함수 템플릿이라는 정확한 분류는 후속 수업에서 살펴봅니다. 이 위치에서는 함수 이름을 <<에 전달하면 해당 연산자가 함수를 호출하므로, 코드에 endl()이라고 쓰지 않습니다. 여기서는 앞 수업의 출력 형태를 유지합니다. 단순한 줄바꿈만 필요한 다른 상황에서는 '\n'도 사용합니다.

한 문장을 처리할 때마다 ‘이번에 추가되는 출력’과 ‘이미 출력한 내용’을 구분하면 실행을 놓치기 어렵습니다. 다음 표의 마지막 줄은 화면 출력이 아니라 main에서 돌아가는 동작입니다.

문장 순서 처리한 동작 처리 후 출력 내용
첫 출력문 Ready와 줄바꿈 Ready 한 줄
둘째 출력문 Open과 줄바꿈 Ready 다음 줄에 Open
셋째 출력문 Close와 줄바꿈 Ready, Open, Close 각 한 줄
return문 main에서 0 반환 추가 출력 없음

예상 출력은 다음과 같습니다.

Ready
Open
Close

직접 빌드하고 실행해서 비교해 보세요. 순서가 다르다면 먼저 저장한 파일과 실행한 프로젝트가 맞는지 확인합니다. 그다음 자신이 적은 순서와 실제 출력문을 한 문장씩 대조합니다.

3 코드의 줄과 화면의 줄은 다릅니다

편집기에서 한 줄을 내려 썼다고 해서 화면도 다음 줄로 내려가지는 않습니다. 아래 예제는 읽기 방식의 차이를 보여 주기 위해 일부러 출력문을 한 줄에 두 개 배치하고, 다른 출력문 하나는 여러 줄에 걸쳐 적었습니다. 평소에는 읽기 편하게 한 문장을 한 줄에 적는 편이 좋습니다.

#include <iostream>

int main()
{
    std::cout << "red"; std::cout << " + ";
    std::cout
        << "blue"
        << std::endl;
    return 0;
}

main의 본문에는 출력문 세 개와 return문 하나가 있습니다. 첫 줄의 세미콜론 두 개는 서로 다른 출력문을 끝냅니다. 이어지는 std::cout부터 std::endl;까지는 여러 줄에 걸친 하나의 출력문입니다. 이 출력문들은 세미콜론으로 끝나지만, C++의 모든 구문이 세미콜론으로 끝나는 것은 아닙니다.

첫 출력문은 red만 출력합니다. 두 번째 출력문은 공백, +, 공백을 덧붙입니다. 세 번째 출력문이 blue와 줄바꿈을 출력하므로 결과는 한 줄입니다.

red + blue

여기서 알아둘 것은 세 가지입니다. 소스 파일의 줄은 사람이 읽기 위한 배치이고, 문장은 프로그램의 동작을 읽는 단위이며, 출력의 줄바꿈은 출력한 내용으로 결정됩니다. 이 예제의 문장 사이 공백과 줄 배치는 바꿀 수 있지만 문자열 내부 공백은 출력되는 데이터입니다. #include 같은 전처리 지시문의 줄이나 // 주석의 줄까지 마음대로 합쳐도 된다는 뜻은 아닙니다.

4 주석을 건너뛰고 return에서 멈추기

주석은 사람에게 설명을 남기는 부분입니다. // 뒤에서 그 줄이 끝날 때까지, 또는 /*와 */ 사이에 적은 내용은 코드로 실행되지 않습니다. 아래 주석 안에 출력문처럼 보이는 글이 있어도 실행할 문장으로 세지 않습니다.

#include <iostream>

int main()
{
    // std::cout << "Hidden" << std::endl;
    std::cout << "Start" << std::endl;
    /* This note spans two lines.
       It does not print anything. */
    return 0;
    std::cout << "Finish" << std::endl;
}

실제로 출력되는 내용은 Start 한 줄입니다. Hidden은 주석 안에 있고, Finish 출력문에는 실행이 도달하지 않습니다. 그 전에 만나는 return 0;이 현재 main의 실행을 끝내기 때문입니다. 여기서 0은 성공 종료를 나타내는 반환값이며 화면에 숫자 0을 출력하라는 뜻이 아닙니다.

return 뒤의 도달할 수 없는 문장도 소스 코드입니다. 실행되지 않는다는 이유로 잘못된 문법을 적어도 되는 영역은 아닙니다. 컴파일러와 경고 설정에 따라 도달 불가능한 코드에 관한 경고가 나올 수 있습니다. 실제 프로그램에서는 이런 문장을 남기지 않는 것이 좋으며, 이 예제는 실행 경계를 확인하기 위한 비교입니다.

한편 문자열 안의 "//"는 주석의 시작이 아닙니다. 큰따옴표 안의 글자를 먼저 구분하고 주석을 찾아야 합니다.

5 빌드 성공과 예상 적중을 구분하기

다음 코드는 두 줄 모두 5를 출력할까요? 먼저 답을 적은 뒤 실행해 보세요.

#include <iostream>

int main()
{
    std::cout << "2+3" << std::endl;
    std::cout << 2 + 3 << std::endl;
    return 0;
}

실제 출력은 다음과 같습니다.

2+3
5

첫 번째 출력문에서는 "2+3" 전체가 문자열입니다. 두 번째 출력문에서는 따옴표가 없는 2 + 3을 계산한 결과가 출력됩니다. 자세한 연산 규칙은 다음 장에서 다루지만, 지금은 글자 자체와 계산할 식을 구분하면 됩니다.

두 줄 모두 5라고 예상했어도 이 프로그램은 정상적으로 빌드됩니다. 컴파일러는 우리가 종이에 적은 예상 결과까지 검사하지 않습니다. 프로그램을 실행한 뒤 기대한 동작과 맞는지 확인하는 과정이 따로 필요합니다.

이 경우 처음 어긋난 곳은 첫 출력문입니다. 두 번째 줄이나 개발 환경을 먼저 바꾸기보다 첫 줄의 큰따옴표가 어떤 의미인지 확인하면 원인을 좁힐 수 있습니다. 출력 순서가 틀렸다면 문장 순서, 줄 수가 틀렸다면 줄바꿈을 넣는 부분, 값이 틀렸다면 출력하는 글자나 식을 확인해 보세요.

6 작은 단위로 확인하는 순서

  • 코드를 실행하기 전에 예상 출력을 적습니다. 공백과 줄바꿈도 표시합니다.
  • main 안에서 지금 볼 문장 하나를 고릅니다. 주석은 실행 대상으로 세지 않습니다.
  • 그 문장이 추가하는 출력만 예상 결과에 덧붙입니다. return을 만나면 그 경로의 추적을 끝냅니다.
  • 저장한 뒤 다시 빌드하고 실행합니다. 예상과 실제가 처음 달라지는 문장을 찾습니다.
  • 한 번에 한 부분만 바꾸고 다시 확인합니다. 수정한 이유도 한 문장으로 적습니다.

선택적으로 Visual Studio 디버거를 사용할 수 있습니다. Debug 구성에서 첫 출력문에 중단점을 놓고 디버깅을 시작한 뒤, 멈추면 F10의 프로시저 단위 실행으로 다음 문장까지 진행해 보세요. 보통 노란 화살표가 가리키는 문장은 다음에 실행할 위치이며 이미 실행이 끝났다는 표시가 아닙니다. 화면 출력이 언제 추가되는지 같이 살펴보면 됩니다.

디버거가 항상 소스 한 줄과 정확히 한 단계씩 대응하는 것은 아닙니다. 여러 문장을 같은 줄에 쓰거나 최적화한 빌드에서는 표시가 이해하기 어려울 수 있습니다. 우선 첫 예제처럼 한 줄에 한 문장을 두고 확인하세요. 이 글에서는 Visual Studio 화면을 직접 실행해 검증하지 않았으므로 메뉴 위치나 단축키가 다르면 해당 설치의 도움말을 확인합니다.

연습

각 예제는 완전한 프로그램입니다. 앞 예제의 파일 내용을 하나씩 교체해서 실행합니다. 정답을 보기 전에 예상 결과와 이유부터 작성해 보세요.

연습 1 출력의 줄 나누기

#include <iostream>

int main()
{
    std::cout << "1";
    std::cout << "2" << std::endl;
    std::cout << "3" << std::endl;
    return 0;
}

출력되는 줄 수와 각 줄의 내용을 적어 보세요. 첫 번째 출력문 뒤에 줄바꿈이 있는지도 확인합니다.

연습 2 문장 세기

#include <iostream>

int main()
{
    std::cout << "A"; std::cout
        << "B" << std::endl;
    return 0;
}

출력문은 몇 개인가요? return문까지 포함한 main 본문의 문장 수와 실제 출력도 적어 보세요.

연습 3 도달하는 문장 찾기

#include <iostream>

int main()
{
    std::cout << "Go" << std::endl;
    // std::cout << "Wait" << std::endl;
    return 0;
    std::cout << "Stop" << std::endl;
}

Go, Wait, Stop 중 실제 출력되는 것을 고르세요. 나머지 두 항목이 출력되지 않는 이유를 각각 설명해 보세요.

연습 4 예상 바로잡기

#include <iostream>

int main()
{
    std::cout << "2+3=";
    std::cout << 2 + 3 << std::endl;
    return 0;
}

2+3=2+3이 출력될 것이라고 예상했습니다. 코드를 바꾸지 않고 이 예상부터 바로잡아 보세요. 이어서 첫 출력문 끝에 std::endl을 추가하면 출력이 어떻게 달라질지도 적어 보세요.

해설

연습 1

두 줄이며 첫 줄은 12, 둘째 줄은 3입니다. 첫 번째 출력은 줄바꿈을 넣지 않습니다. 두 번째 출력이 2를 이어 붙인 뒤 줄을 바꿉니다.

12
3

연습 2

출력문은 두 개, return문을 포함하면 문장은 세 개입니다. 둘째 출력문은 두 소스 줄에 걸쳐 있지만 하나의 문장입니다. 화면에는 AB가 한 줄로 출력됩니다.

연습 3

Go만 출력됩니다. Wait 출력문은 // 주석 안에 있습니다. Stop 출력문은 return 이후에 있어 이 실행 경로에서는 도달하지 않습니다.

연습 4

첫 출력문은 2+3=라는 글자를 그대로 출력하고, 두 번째 출력문은 2+3의 계산 결과인 5를 출력합니다. 따라서 한 줄에 2+3=5가 나옵니다. 첫 출력문에도 std::endl을 넣으면 2+3=와 5가 서로 다른 줄에 나옵니다. 다음 두 출력문으로 바꾸어 확인할 수 있습니다.

    std::cout << "2+3=" << std::endl;
    std::cout << 2 + 3 << std::endl;

정리

짧은 코드를 읽을 때는 지금 실행할 문장과 지금까지 생긴 결과를 나누어 적어 보세요. 줄 수만 보고 실행 횟수를 세거나, 주석까지 실행한다고 생각하거나, 빌드 성공을 원하는 동작의 증거로 삼으면 결과를 놓치기 쉽습니다. 다음 수업에서는 변수에 이름을 붙이고 값을 초기화하면서, 출력뿐 아니라 값의 변화도 함께 따라가겠습니다.

참고 자료와 확인 범위

C++20 공개 작업 초안 N4861의 [intro.execution], [stmt.pre], [stmt.return], [basic.start.main], [lex.comment], [ostream.manip]을 대조했습니다. 현재 예제의 단순한 순차 실행에 한정한 설명이며 한 표현식 내부의 복잡한 평가 순서나 동시 실행까지 일반화하지 않습니다. https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2020/n4861.pdf https://learn.microsoft.com/en-us/cpp/cpp/overview-of-cpp-statements?view=msvc-170 https://learn.microsoft.com/en-us/cpp/cpp/comments-cpp?view=msvc-170 https://learn.microsoft.com/en-us/cpp/standard-library/ostream-functions?view=msvc-170#endl

Microsoft Visual Studio 디버거의 코드 탐색 안내 https://learn.microsoft.com/en-us/visualstudio/debugger/navigating-through-code-with-the-debugger?view=visualstudio

예제는 GCC 14.2.0의 C++20 모드에서 실제 빌드·실행 결과를 대조했습니다. MSVC 빌드와 Visual Studio GUI 실습은 실행하지 않았습니다. 그림은 AI로 새로 만든 학습용 비유이며 정확한 실행 순서는 본문의 코드와 추적 표를 기준으로 확인합니다.
